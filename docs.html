Conventions

  • Every resource is a JSON file and ends in .json.
  • Response shape: {"data": ..., "meta": {...}} with apiVersion, schemaVersion, dataset.version.
  • References and enumerations use {id, slug, name, path}; unknown targets stay visible as {id, "resolved": false}.
  • Errors: application/problem+json (RFC 9457).
  • Caching: ETag and 304; static max-age=600, dynamic max-age=60.
  • path is relative to the API base (meta.endpoints.static), not to the host.

Examples

# Item including crafting and recycling
curl -s https://haxxorhardy.github.io/rust.api-site/v1/items/explosives.json | jq .data.craft

# Name, stack size and path only
curl -s https://haxxorhardy.github.io/rust.api-site/v1/items/index.json | jq '.data[0] | {name, stackSize, path}'

# Raid cost for one building block (8 C4 for an armored wall)
curl -s https://haxxorhardy.github.io/rust.api-site/v1/building/armored-wall.json | jq .data.raid.explosive[0]

# Search via the Python client
python client/rustapi.py search beef --types item

Limits

  • Read-only: there are no write, auth or upload endpoints.
  • Static hosting cannot evaluate query parameters; precomputed views cover the common cases.
  • requiredItems in raid costs comes from the upstream data; only crafts and totalCost are derived and marked as such.
  • Skin-to-item matching uses the display name and is only set for unambiguous matches (matchedBy).
